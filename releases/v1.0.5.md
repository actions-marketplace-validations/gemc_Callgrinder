# Callgrinder Release v1.0.5

This version includes:

- Inclusive **% of run** no longer exceeds 100% for a single symbol.

<br/>

# Release notes

- Fixed the inclusive **% of run** column reaching values like 256%, 191%, and 128%. When a demangled
  symbol lives in more than one object — common with GEMC's per-detector plugins and COMDAT template copies
  such as the PTL task dispatch — it appears as several rows once the object tag is stripped. Their
  inclusive subtrees overlap through shared callees and nest, so summing them double counted the cost. A
  symbol's inclusive cost is now the dominant single row (max), which is bounded by the program total,
  instead of the sum. This matches the earlier self-cost fix (self is summed per name because instructions
  are disjoint); both the category table and the top-routines table use the same aggregation.
- Clarified the summary note: **Self %** (Self Mcycles / total) is the reliable, non-overlapping share and
  no single row exceeds 100%; **% of run** is inclusive and its subtrees still overlap, so it can sum past
  100% across rows even though no single row does.

<br/>

## Tests

- Added a regression test asserting that a symbol appearing in several objects keeps its inclusive cost as
  the dominant row (max) and its self cost summed, so neither share exceeds the program total.
