# Callgrinder Release v1.0.12

This version includes:

- Compact project caller names beside routines, without source/package lists.
- Correct call counts for profiles containing compressed jump targets.

<br/>

# Release notes

- Remove the **Source / package** and separate nearest-project-caller columns from both summary tables.
  Show nearest project function names in parentheses beside each routine or category entry symbol.
  Runtime calls such as `malloc` and `strtod` can identify the calling application or library function,
  including paths through C++ runtime helpers. Show up to three distinct names and `+N more` for the rest;
  JSON retains full caller signatures, distances, and source metadata.
- Accept a valid zero incoming-call count for `main` in the CI smoke test. Measured execution does not
  require a recorded incoming call arc; call counts continue to reflect the raw profile.
- Match actual failure diagnostics when checking summary availability, allowing normal explanatory text
  about unavailable data.
- Read function and file name definitions from jump targets, preserving call counts and caller attribution
  when later call records reuse those compressed names. Jump execution counts are not counted as calls.

<br/>
