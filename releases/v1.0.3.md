# Callgrinder Release v1.0.3

This version includes:

- Actually profile the target program: follow `exec` into it instead of profiling the launching shell.

<br/>

# Release notes

- The callgrind run now passes `--trace-children=yes`. Valgrind does not follow `exec()` by default, so the
  `bash -c "exec <command>"` wrapper meant the shell was profiled and the real program ran un-instrumented,
  producing an empty callgrind file. Following children profiles the program.
- Each process now writes its own `callgrind.out.<name>.<pid>` file; Callgrinder keeps one as the profile —
  the process whose command matches the new optional `program` input (for example `gemc`), otherwise the
  largest file (the real workload dominates). The result is written to `callgrind.out.<name>` as before.

<br/>

## Inputs

- `program` (action) / `--program NAME` (CLI): the program to keep when the command spawns several processes.
