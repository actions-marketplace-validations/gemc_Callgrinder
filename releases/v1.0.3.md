# Callgrinder Release v1.0.3

This version includes:

- Profile only the target program: run valgrind on it directly instead of through a shell that execs it.

<br/>

# Release notes

- The run is now `bash -c "exec valgrind … <command>"` instead of `valgrind bash -c "exec <command>"`.
  Valgrind does not follow `exec()` by default, so with the old shape the launching shell was profiled and
  the program ran un-instrumented, producing an empty callgrind file. Now bash execs valgrind, which runs the
  command's program as its direct child — so **only that program is profiled**, not the shell and not the
  program's own child processes.
- The `command` must therefore be a program invocation (for example `gemc card.yaml -n 100`), not a wrapper
  script that itself execs the program. Set up any environment before the run (in a workflow prep step), then
  give Callgrinder the direct command.
