# Callgrinder Release v1.0.2

This version includes:

- Resilient summarizing: a `callgrind_annotate` failure no longer crashes the action.

<br/>

# Release notes

- Each `callgrind_annotate` pass is now best effort. A broken `--inclusive` pass no longer prevents the
  self-cost (top-routines) table, and a callgrind file that `callgrind_annotate` cannot read produces a
  visible diagnostic section — including the callgrind file size — instead of failing the job. The raw
  callgrind file is still written and can be inspected with qcachegrind.
- An empty or tiny callgrind file is called out explicitly: it means the profiled command produced no event
  data (it did not run to completion under callgrind), which is a workload problem, not a Callgrinder one.

<br/>

## Tests

- Added a test that `summarizeCallgrind` degrades to a diagnostic section (rather than throwing) when
  `callgrind_annotate` is unavailable or the file is empty.
